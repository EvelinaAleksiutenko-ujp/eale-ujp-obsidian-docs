## Thinking about Image Registration pipeline
As now I were thinking that we have only one(+one public) set of ct-cbct how we should move forward.
I decided to take a look again on every model of our current pipeline which can be found in Adaptive radiotherapy pipelines diagrams.
Also I took a look on the paper: https://arxiv.org/pdf/2102.00590

I took a quick look on [Adam's work regarding registration](https://gitlab.ujp.cz/reg_ai/ai-deformable-registration) and it looks like  and it seems that he was not using any synthetically generated image ad were just training DIR between CT-CBCT(but the source or exact organ is not mentioned). So for now it can be as one ct-cbct for HaN from Motol or one public for Pancreatis.
Citation from https://gitlab.ujp.cz/reg_ai/ai-deformable-registration/-/wikis/home/Deformable-Registration: **5.12.2025**: we still dont have masks for CT-CBCT pairs. Due to that the development is paused. Based on [this paper](https://arxiv.org/pdf/2102.00590), we decided that we would like to develop gan for generating synthetic images CT-CBCT.
1. we should be able to generate CT from CBCT
2. segment this sythetic CT -> get segmented maps for original CBCT
3. we should be able to train deformable registration or atleast be able to evaluate results

Out of this info + talk with the Denis I updated the diagram https://drive.google.com/file/d/1LPueXRhzkZsvzjU5qGKcPHNJ5_pfDMFz/view?usp=sharing with definition how exactly we are planning to use pCT RTS and and sCT RTS.

1. While being synthetically generated
2. While being segmented by our model which is not trained on sCT's
